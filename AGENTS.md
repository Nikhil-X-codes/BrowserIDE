## 1. What this project is

**CloudAIIDE** is an AI-native cloud IDE. A user types a prompt, an autonomous
agent writes a multi-file project into a real-time database, and a Node.js
runtime boots **inside the browser tab** to run it — no server-side sandbox.

The one mental model that explains most of the code:

> **Convex is the filesystem.** Files are rows, not disk. Everything — the file
> explorer, the CodeMirror editor, the AI agent's tool calls, the GitHub
> importer, and the in-browser runtime — reads and writes the same `files`
> table. Because clients subscribe to live queries, a write from a background
> job appears in the UI with no polling and no refresh.

Stack: Next.js 16 (App Router) · React 19 · TypeScript 5 (strict) · Convex ·
Clerk · Inngest · Groq · WebContainers · Tailwind 4 + Radix/shadcn · Zustand ·
Zod 4.

## 3. Architecture: the trust boundary

There are **two doors into Convex**, and picking the wrong one is the most
common way to introduce a security bug here.

```
Browser (React)                  Next.js server / Inngest jobs
      │                                       │
      │ ConvexReactClient (WebSocket)         │ ConvexHttpClient (src/lib/convex-client.ts)
      │ + Clerk JWT                           │ + CLOUDAIIDE_CONVEX_INTERNAL_KEY
      ▼                                       ▼
convex/projects.ts                     convex/system.ts
convex/files.ts                        ("internal" API — shared-secret guarded)
convex/conversations.ts
("client" API — verifyAuth + ownership)
```

### Door 1 — client API (`projects.ts`, `files.ts`, `conversations.ts`)

Called from React via `useQuery` / `useMutation`. **Every handler must**:

```ts
const identity = await verifyAuth(ctx);              // throws "Unauthorized"
const project = await ctx.db.get("projects", args.projectId);
if (!project) throw new Error("Project not found");
if (project.ownerId !== identity.subject)            // ownership, not just auth
  throw new Error("Unauthorized to access this project");
```

Authentication is **not** authorization. Every function that touches a
`files`/`conversations`/`messages` row must walk up to the owning project and
compare `ownerId` against `identity.subject`. Copy the pattern from
`convex/files.ts:7-27` verbatim.

The **only** unauthenticated client queries are `projects.getPublicProject` and
`files.getPublicFiles` for `/share/[projectId]`, which are strictly read-only,
must check `project.isPublic === true`, and must never return conversations,
messages, or secrets. See `SECURITY.md` for full trust-boundary details.

### Door 2 — internal API (`convex/system.ts`)

Called only from trusted server code (API routes, Inngest jobs) via the
`ConvexHttpClient` in `src/lib/convex-client.ts`. These are registered as
**public** `query`/`mutation` — deliberately, because `ConvexHttpClient` cannot
call `internalMutation` — so the shared secret **is** the entire access control:

```ts
export const doThing = mutation({
  args: { internalKey: v.string(), /* ... */ },
  handler: async (ctx, args) => {
    validateInternalKey(args.internalKey);   // ← NEVER omit or move this
    // ...
  },
});
```

Rules for `convex/system.ts`:

- `validateInternalKey(args.internalKey)` is the **first statement** of every
  handler. A `system.*` function without it is an unauthenticated,
  internet-reachable write to any user's data.
- These functions take `projectId`/`fileId` on trust. Ownership is enforced by
  the *caller* (the API route checks Clerk `userId` before dispatching). If you
  add a new route that calls `system.*`, you own that check.
- Never import `api.system.*` into anything under `src/components/`,
  `src/features/**/components/`, or `src/features/**/hooks/`. The internal key
  must never reach the browser bundle.

## 5. Convex conventions

**Read `convex/_generated/ai/guidelines.md` before writing any Convex code.** It
targets Convex `^1.41.0` and overrides older patterns you may have memorized.
The most important consequence:

### Table-name-first DB API (current)

```ts
await ctx.db.get("projects", id);
await ctx.db.patch("files", id, { content, updatedAt: Date.now() });
await ctx.db.replace("files", id, doc);
await ctx.db.delete("files", id);
```

⚠️ **`convex/system.ts` is inconsistent** — several handlers still use the
legacy 2-arg form (`ctx.db.get(args.conversationId)`,
`ctx.db.patch(args.messageId, {...})`) while others use the new 3-arg form.
Write **new** code with the table-name-first API. Only migrate the legacy calls
if that's the task you were given; don't drive-by refactor them.

### Other Convex rules that bite in this repo

- **Always query through an index**, never `.filter()` on a table scan. Existing
  indexes: `projects.by_owner`, `files.by_project`, `files.by_parent`,
  `files.by_project_parent`, `conversations.by_project`,
  `messages.by_conversation`, `messages.by_project_status`. Adding a query
  shape usually means adding an index in `schema.ts`.
- **Argument validators are mandatory** on every function.
- `.collect()` is unbounded. The file tree deliberately collects a whole project
  (`files.getFiles`) because the editor and WebContainer need the full tree —
  that's an accepted trade-off, not a template. Prefer `.take()` / pagination
  for anything new.
- **Never `Date.now()` inside a query** (queries don't re-run as time passes).
  Mutations and actions are fine — that's why `updatedAt: Date.now()` appears
  everywhere in mutations.
- **Folder deletes are recursive and must clean storage.** See
  `convex/files.ts:324-354`: recurse into children first, `ctx.storage.delete`
  any `storageId`, then delete the row. Skipping the storage delete orphans
  blobs forever.
- **Name collisions are checked per parent folder, per type.** A file and a
  folder may share a name; two files may not. Preserve this when adding write
  paths.
- Mutations that change a file also bump the owning project's `updatedAt` —
  the dashboard sorts on it.

### Data model quick reference

- `files` is a **tree**, not paths: `parentId` links child → parent; `parentId:
  undefined` means project root. Paths are derived by walking up the chain
  (`convex/files.ts` `getFilePath`, `src/features/preview/utils/file-tree.ts`).
- A file row is **either** text (`content`) **or** binary (`storageId` →
  Convex `_storage`). Never both. Binaries are skipped when mounting into the
  WebContainer.
- `messages.status` drives the UI: `processing` → `completed` | `cancelled`.

## 6. The AI agent (Inngest + Agent Kit)

`src/features/conversations/inngest/process-message.ts` is the heart of the app.

- Triggered by the `message/sent` event; cancellable via `message/cancel`
  (matched on `event.data.messageId`).
- A **network router loop** (`maxIter: 20`) re-runs the agent until it produces
  a text response **with no accompanying tool calls**. The model can emit text
  *and* tool calls in one turn — stopping on "has text" alone truncates the
  agent mid-task. Don't "simplify" that router.
- `onFailure` writes a friendly apology into the assistant message so the UI
  never hangs on a `processing` row. Any new job that owns a user-visible status
  needs the same treatment (see `import-github-repo.ts` / `export-to-github.ts`).
- Conversation history is injected into the **system prompt** (last 10 messages,
  minus the in-flight one), not as chat turns.

### Model choices are load-bearing — do not "upgrade" them casually

The code comments explain constraints discovered the hard way:

| Use | Model | Why |
| :--- | :--- | :--- |
| Coding agent | `openai/gpt-oss-20b` | Llama 3.x on Groq emits malformed `<function=...>` tool calls that Groq rejects as HTTP 500. GPT-OSS emits valid JSON tool calls. |
| Title generator | `llama-3.1-8b-instant` | Cheap, 50-token cap |
| Quick edit | `llama-3.3-70b-versatile` (`DEFAULT_GROQ_MODEL`) | Quality on a 2048-token budget |
| Inline autocomplete | `llama-3.1-8b-instant` (`FAST_GROQ_MODEL`) | Latency + free-tier rate limits |

`max_completion_tokens: 2000` on the agent is a **rate-limit workaround**: the
Groq free tier caps this model at ~8k tokens/minute and returns HTTP 413 when
`prompt + max_completion_tokens` exceeds it. The agent's prompt grows as it
reads files, so the completion budget stays low to leave ~6k of headroom. Raising
it makes long conversations fail. Consequence: a single agent file write is
capped at roughly 150 lines.

### Adding an agent tool

1. New file in `src/features/conversations/inngest/tools/<name>.ts`.
2. Export a factory `createXTool({ internalKey, projectId? })` returning
   `createTool({ name, description, parameters: z.object({...}), handler })`.
3. Describe every parameter with `.describe()` — the model only sees that text.
   Existing tools use `parentId: ""` to mean "project root" because the model
   handles empty strings better than omitted optionals.
4. **Return error strings, never throw.** `return \`Error: ...\`` lets the agent
   self-correct; a throw burns an Inngest retry. Follow
   `tools/create-files.ts` — it validates params with a separate
   `paramsSchema.safeParse`, verifies the parent is a folder, and reports
   partial success ("Created 3 file(s)… Failed: x (already exists)").
5. Wrap real work in `toolStep?.run("...")` so it checkpoints.
6. Register it in the `tools: [...]` array in `process-message.ts`.

### Adding an Inngest function

Register it in the `functions: [...]` array of
`src/app/api/inngest/route.ts` — **a function not listed there never runs.**
(`src/inngest/functions.ts` holds `demoGenerate` / `demoError`, which are
deliberately *not* registered; they're scratch examples.)

Event names in use: `message/sent`, `message/cancel`, `github/import.repo`,
`github/export.repo`, `github/export.cancel`.

Long work must be **batched into bounded steps** — see `FILE_BATCH_SIZE = 20` in
`import-github-repo.ts`, so a transient failure retries one batch instead of
restarting a 5,000-file import. Use `NonRetriableError` for config/validation
failures that retrying cannot fix (missing internal key, missing conversation).

## 7. API route conventions

Every handler in `src/app/api/**/route.ts` follows this shape:

```ts
const { userId } = await auth();                    // @clerk/nextjs/server
if (!userId) return NextResponse.json({ error: "Unauthorized" }, { status: 401 });

const internalKey = process.env.CLOUDAIIDE_CONVEX_INTERNAL_KEY;
if (!internalKey) return NextResponse.json({ error: "..." }, { status: 500 });

const body = await request.json();
const { ... } = requestSchema.parse(body);          // module-level Zod schema

// ...convex.query/mutation(api.system.*, { internalKey, ... })
// ...inngest.send({ name: "...", data: { ... } })
return NextResponse.json({ success: true, eventId: event.ids[0], ... });
```

- GitHub OAuth tokens come from Clerk, never from env:
  `(await clerkClient()).users.getUserOauthAccessToken(userId, "github")`, then
  400 with a "reconnect your GitHub account" message if absent.
- Routes return JSON errors with meaningful status codes; the client surfaces
  them with `sonner` toasts.
- Client → route calls use `ky` with an `AbortSignal`, a timeout, `retry: 0`,
  and Zod validation on **both** request and response
  (`src/features/editor/extensions/quick-edit/fetcher.ts` is the model).

## 8. Frontend conventions

Match the surrounding code:

- **Components**: arrow functions, **named** exports
  (`export const ProjectIdView = ({ projectId }: { projectId: Id<"projects"> }) => …`).
  App Router `page.tsx` / `layout.tsx` use **default** exports.
- **`"use client"`** at the top of any component using hooks, Convex, or DOM.
  Pages stay server components: `await params`, cast the id, render the feature
  view (`src/app/projects/[projectId]/page.tsx`).
- **Imports** are grouped, blank line between groups: third-party → `@/…`
  aliases → relative. Convex generated code is always **relative**
  (`../../../../convex/_generated/api`) because `@/*` maps only to `./src/*`.
- **Data access goes through a hook** in `src/features/<domain>/hooks/`, not
  `useQuery(api.…)` inline in a component. Conditional queries use the Convex
  `"skip"` sentinel: `useQuery(api.files.getFiles, projectId ? { projectId } : "skip")`.
- **Optimistic updates** on file-tree mutations via `.withOptimisticUpdate()`
  patching `api.files.getFolderContents`. Keep the shared `sortFiles` ordering
  (folders first, then alphabetical) identical to the server's sort in
  `convex/files.ts:128-135` — divergence causes a visible re-shuffle.
- **Client state**: Zustand for editor tabs (`use-editor-store.ts`, keyed by
  projectId with VS Code-style preview/pinned tab semantics). Server state is
  Convex — do not mirror Convex data into Zustand.
- **Styling**: Tailwind 4 with `cn()` from `@/lib/utils`. New primitives come
  from shadcn (`components.json`: new-york, neutral, cssVariables, lucide).
  Theme is `next-themes`, class attribute, dark by default.
- **Types**: `Id<"table">` / `Doc<"table">` from `convex/_generated/dataModel`.
  TypeScript is `strict` — no `any`, no non-null assertions on user data.

## 9. WebContainer constraints (`src/features/preview/`)

- Requires **cross-origin isolation**. The COOP/COEP headers in `next.config.ts`
  (`Cross-Origin-Opener-Policy: same-origin`,
  `Cross-Origin-Embedder-Policy: credentialless`) are **load-bearing** — removing
  or narrowing them breaks the preview entirely. `WebContainer.boot({ coep:
  "credentialless" })` must stay in sync with the header.
- **One instance per tab.** `use-webcontainer.ts` keeps a module-level singleton
  plus a `bootPromise` guard; booting twice throws. Tear down via `restart()`.
- The mount tree is derived from the flat Convex rows by `buildFileTree()`.
  Binary files (`storageId`) are **skipped** — they can't be mounted.
- After `status === "running"`, file edits are pushed with
  `container.fs.writeFile` for hot reload rather than remounting.
- Install/dev commands come from `project.settings` and fall back to
  `npm install` / `npm run dev`; they're split naively on spaces.
- Chromium-based browsers only.

## 10. Environment & secrets

Copy `.env.example` → `.env.local`. Two variables must be set in **both**
`.env.local` *and* the Convex deployment's env vars:

- `CLOUDAIIDE_CONVEX_INTERNAL_KEY` (generate: `openssl rand -hex 32`)
- `CLERK_JWT_ISSUER_DOMAIN` (needs a Clerk JWT template named `convex`)

Others: `NEXT_PUBLIC_CONVEX_URL`, `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`,
`CLERK_SECRET_KEY`, `GROQ_API_KEY`, `INNGEST_EVENT_KEY`, `INNGEST_SIGNING_KEY`,
`FIRECRAWL_API_KEY`.

- `.env*` is gitignored except `.env.example`. **Never** print, commit, or paste
  the contents of `.env.local` into code, comments, or a PR body.
- Only `NEXT_PUBLIC_*` reaches the browser. Never prefix a secret with it.

## 11. Hard rules

1. **Never edit `convex/_generated/`.** Run `npx convex dev` instead.
2. **Never remove `validateInternalKey`** from a `system.ts` handler, and never
   import `api.system.*` into client-side code.
3. **Never add a client-facing Convex function without `verifyAuth` + an
   `ownerId === identity.subject` check.**
4. **Never register an Inngest function you forgot to add to
   `src/app/api/inngest/route.ts`.**
5. **Never claim tests pass** without running `npm test` after your last edit.
6. **Never weaken the COOP/COEP headers** in `next.config.ts`.
7. **Don't raise Groq token budgets** (`max_completion_tokens`) without saying
   it requires a paid tier — HTTP 413 on the free tier is the failure mode.
8. Don't commit `.env.local`, `tsconfig.tsbuildinfo`, `.next/`, or `.vercel/`.
9. Prefer editing existing files over adding new ones; don't create README/docs
   files unless asked.
